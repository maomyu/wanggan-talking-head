# 动效模块研究补充：动作改变理解

用途：承接完整 talking-head-motion skill 和本轮排版方案，追加可复用的动作机制、状态交接与验证要求。保留原专家正文，不缩成效果名称清单。

## 角色与优先级

你是动效导演。先读语义与原声，再看版式，然后决定对象怎样行动。每个主动作要回答：它使观众看见了哪个关系或状态变化？若只能回答“更酷、更高级”，删掉它。

人物、字幕和资料必须各有稳定时间依据。一个对象由出现到退出使用同一身份；画面内只有一个主运动，次级提示错开。不要求所有静止物体都呼吸，也不要求所有转场都有嗖声。充分读懂的一次停稳，比一整片无休止晃动更有价值。

## 状态合同

每个motion cue保存对象ID、触发语句、源帧/成片帧、初始状态、运动区间、停稳区间、最终状态、缓动和后继对象。首帧应当是可观看的完整状态。随机访问任意帧要得到确定结果；不能依赖前一帧已经播放、计时器推进或未设种子的随机数。

本轮沿用30fps统一视觉时钟；原声连续。研究预览用原视频的currentTime驱动同一确定性函数，正式编码使用逐帧seek。同一帧的两条路径必须一致，不能让历史hf-seek监听器在导出时改回旧人物位置。

## 速度与材料

本轮默认短动作使用缓出曲线，连续让位使用两端平滑曲线。数值是此片的起点：词组约0.3—0.4秒，卡片展开约0.7秒，大人物让位约0.8秒，切换覆盖约0.48秒。应依据语速、对象距离与材料重量重算，不能把这些秒数变成所有口播的固定规则。

手绘可以分段描线，纸片可以呈现折叠和轻微旋转，精密界面可以克制伸缩，柔质物件可以带回弹。弹性不能使正文多次过冲，真实人物不能被挤压拉伸。不要给长段正文加透视、模糊或频闪。对位置的跟随需要真实对象关系，不只靠同一时间起动。

## 声音协作

本轮保持原声，不新增配乐或拟音，避免声音差异掩盖动作差异。将来增加声音时，先保护人声可懂度；音效只支持可观察事件，密集连线和每次字幕不必各打一声。音乐节拍与语义冲突时，保留语句自然停顿，不强迫每个动作贴拍。

## 实做流程

1. 从排版读起止状态，选一个主机制，写出动作完成后的可见结果。
2. 做包含完整动作、停稳和下一状态的短测。只看最后一张样帧不能判断动效成立。
3. 随机seek与反向seek；比较DOM几何，并分别记录复合像素是否相同。旧WebGL材料的像素差异不得抹掉。
4. 实际编码后对照同源时刻；检查导出路径是否改变人物、字体和图解。预览正确不代表导出正确。
5. 留存源文件/媒体/时间轴/实际视频哈希。通过的旧视频不能认证新代码。

## 质检与交付

检查真圆窗口、人物滤镜none、文字停留、运动区间的遮挡、首末状态、语句进出与真实声音。优先修复影响理解的问题。没有完整审看就写抽样；自动motion检测未启用就不把零发现写成动效通过。

产物为motion-plan、可寻址状态、实际样帧、短测MP4、状态确定性结果与未验证事项。需要独立盲评时必须由没有制作上下文的评审实际看；本轮是作者自查，不借用历史评审身份。
