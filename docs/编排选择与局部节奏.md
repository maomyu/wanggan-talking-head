# 编排选择与局部节奏

画风回答“用什么视觉语言”，编排回答“观众跟着谁、怎样理解”。母画风、分支、组件与七套视觉配方继续原样管理。人物主导和连续图解是两套可选编排，不增加母画风数量，也不是必须贯穿每一秒的硬模板。实际计划仍由十一类技能共同完成。

## 选择与判断

| 编排 | 适合的理解任务 | 空间、动作、镜头、转场共同原则 |
|---|---|---|
| presenter 人物主导 | 观点、经历、态度、需要人物承担信任的讲述 | 人物保持主要阅读重心；图片或图解在旁侧/下方辅助必要句子；辅助物件有明确出现、结果和退出，镜头服务主讲，不用连续大运动抢注意 |
| diagram 连续图解 | 因果、对比、转折、机制、数量或条件变化需要连续解释 | 人物以原色圆窗让出解释空间；同一对象贯穿初态→动作→结果→下一段；局部看清后回到关系全景，转场由上一个结果接住下一个条件 |

不要只凭“财经”“知识”这样的题材标签决定。读懂本次语句，指出最难理解的关系和人物表演价值，再选编排。明确用户选择优先；未指定用auto，由代理记录选择理由，必要时逐段混合但写清主线和交接。不为展示两套能力强行各占一半，不把原案例的大圆窗尺寸、耳机、单位块或秒点变成通用规则。

人物主导也可出现图解，连续图解也可回到人物。区分依据是主要理解任务和注意力连续性。图解段先保住对象身份、变化的条件和可见结果，再追求运动丰富；人物段先保住表情、语句与阅读主次，再安排辅助动作。图片是对象、证据、环境、对比基准或结果中的一种，先有任务再补图。

## 与十一类协作

选择编排不另造第十二套专业计划。`orchestration.json`只登记选择和约束；真正实现写入原十一份计划。信息组织保留原句与关系；造型维护部件、锚点和对象身份；版式维护人物/文字/图片主次和保护区；物体动效维护路径与状态；镜头维护观察变换；转场维护两端承接；节奏维护事件与读窗。配色、材质、光影和画风继承已认可决定，遇到真实冲突再最小修复。

明确换编排会联动这七类，CLI列出改写范围与复查范围。改画风不自动换编排，改节奏也不自动换编排。七套视觉配方与两套编排是可设计的两个选择维度；目前新增编排的实际完整验证是写实极简同源案例，其他视觉组合仍须适配和检查，不能宣称已经验证十四条组合。

新素材用`init --recipe <视觉配方> --orchestration presenter|diagram|auto`。也可在`--request`里写“采用人物主导编排”。入口导入自有素材后保持awaiting-design，不注入示例文案或固定动作。关键词只是提示；保留、否定、比较研究和上下文可能改变含义，由代理确认后显式传ID。不把路由输出冒充创意完成。

## 只改节奏

先界定用户希望改变的是“更早看清对比”“转折揭示更干脆”“结尾缓下来”中的哪一种。不要把“节奏快一点”直接变成整体倍速。读真实原声，标出语义重音、条件、否定与结果可读窗；明确当前拖沓或抢读的句段。

使用`revise --from <原项目> --out <新版本> --axes rhythm --request <需求>`。十一类工程也支持从明确的“只改节奏”请求推断该轴；显式轴优先。原始工程不覆盖。源片、原声、根目录`timing.json`的源映射/字幕、其他十份专业计划、母画风/分支和编排选择均受保护。节奏自己的文件是`plans/timing.json`，与根目录同名文件承担不同职责。

在适用机制中，物体轨迹和镜头轨迹保留空间点，用符号事件（如本片的compareReady）引用节奏表。节奏模块调整这个事件的帧号；不能偷偷改空间路径、对象数量、字形或人物时序。读窗、密度和动作区间同步维护，speechAnchors属于原声事实，不能为了动作漂移原句锚点。若旧实现把时间硬编码在各处，先做有证据的等价解耦，记录兼容修复，再实施节奏修改；未经复现不声称只改了一份文件。

检查事件存在、帧界、路径顺序、动作正向区间后，再检查真实画面：动作是否先落定再读、否定是否被提前泄露、前后遮挡是否新增、结尾是否真的减少新信息。比较修改前后全部相关帧和关键结果态。结果态相同指对象/空间/语义一致，不要求有损视频像素逐字节一致。技术检查和真实1×看听分别记录。

已认可的示范B2只改8个事件，并调整相应读窗与密度；其他十份计划、原片、原声、字幕和人物时序保持，1100帧状态对照中142帧空间展开有差别，五处结果态一致。详见[同源节奏示例](../examples/orchestrations/rhythm-only.json)与[实际检查记录](../evidence/orchestrations/rhythm-only.json)。这些秒点只属于这个源片；新文案重新设计。

只改配色、字号、镜头等其他模块同样使用原有revise机制。只允许选中计划改写，关联复查不是全部重做；确有跨模块兼容修复用`--allow-dependent <轴ID> --reason <原因>`记录。源EDL真变动必须另行建立源映射并重排所有字幕、音频和事件，不能借节奏修改绕过保护。

## 命令与复现边界

```sh
node scripts/studio.mjs orchestrations
node scripts/studio.mjs route --request "保留画风，改成人物主导编排"
node scripts/studio.mjs init --project /path/to/new-film --source /path/to/own.mp4 --recipe minimal --orchestration diagram
node scripts/studio.mjs revise --from /path/to/film --out /path/to/film-v2 --orchestration presenter --request "保留画风，改成人物主导"
node scripts/studio.mjs revise --from /path/to/film --out /path/to/film-rhythm --axes rhythm --request "只调整节奏，让对比更早落定，结尾更从容"
node scripts/studio.mjs reproduce --project /path/to/reference --source /path/to/original-case-840-proxy.mp4 --recipe minimal --orchestration diagram
```

reproduce是明确、哈希绑定的同源复现，不是任意新素材自动成片。未加orchestration时保留原七套配方的复现行为。新两套代码和22份专业计划在`examples/orchestrations/`；单独节奏修改另有认可示例。原片、原声和最终视频留在制作项目外部，不上传到插件仓库。固定运行环境和旧有效实现保持。

完成后保留原素材、源码、最终片和关键证据，只清理本次可重建帧序列、缓存、失败中间编码和隔离测试工程。不要因正式收录删除用户仍在对照的三条视频或停止其父预览服务。
