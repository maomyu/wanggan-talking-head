# 分类与配方 · 1.21.0

当前完整母画风表、统一入口、源码和验证范围见[19套配方与统一入口](19套配方与统一入口.md)。19套母画风默认配方+技术蓝图分支共20套，旧七套实现保留。以下七套表保留为最初收录沿革。

正式入口是 `skills/talking-head-video/SKILL.md`，按任务读取十一类协作统筹与完整专业技能。新分类解决选择与职责问题；成片仍需根据本次文案设计、实现与验收。

| 管理对象 | 登记位置 | 用法 |
|---|---|---|
| 母画风 | registry/families.json | 19个有独立造型、空间或媒介语言的母入口，不按配色凑数 |
| 分支 | registry/branches.json | 38个依附母画风的表达方向；如工程蓝图属于技术图形与界面 |
| 组件来源 | registry/components.json | 43项可提取的排版、材质、造型、场景或效果来源；保留原实现与适用边界 |
| 专业设计标准 | registry/standards.json | 85项，分属十一类；是专业语言，不等于85个任意组合的通用渲染组件 |
| 配方 | recipes/*.json | 一套母画风/分支选择及十一类协作选择；单片只使用真正需要的技法 |
| 编排 | registry/orchestrations.json | 人物主导与连续图解，独立于画风选择，十一类共同实现 |
| 历史映射 | registry/legacy-map.json | 原100项ID、原名、来源哈希与新归属；旧模板、图片和证据原地保留 |

其他母画风可以在配方的`art-style`直接引用`Fxx`，例如透明水彩引用F17，读取同一母画风规则，无需再造一组近义标准。母画风的默认分支记录在family内，不为统一数量再增加一批重复分支。组件的“已实现研究子集”只指相应历史案例；没有跨母画风适配证据时保留参考状态。旧完整模板不是即插即用组件。

十一类分别是：主画风、配色、材质外观、造型呈现、物体动效、镜头、转场、字体版式、光影质感、信息组织、节奏。字段归属和交接见[协作合同](协作合同.md)。源片精剪/EDL、人声、字幕映射、编码与交付由统筹管理；不因未另列审美类别而省略。

## 最初七套认可配方（历史沿革）

| 配方ID | 层级选择 | 编排特征 |
|---|---|---|
| editorial-print | 编辑出版；拼贴与印刷为辅助语言 | 纸页层次、衬线标题、批注、翻面与纸页接续 |
| minimal | 写实与摄影影像，写实极简默认方向 | 摄影物件、留白、同尺度比较、取舍与干净承接 |
| blueprint | 技术图形与界面 → 工程蓝图A09 | 同一工程平面取景、轴线延展剖面、扫描和导轨回收 |
| clay | 立体造型，柔质立体默认方向 | 固定本地Three.js r181、哑光模型、接触关系和空间机位 |
| ink | 水墨，水墨写意方向 | 干笔墨阶、纸白留白、墨幕退开与笔路承接 |
| line | 线描与素描，单线手绘方向 | 统一线宽、逐步描物、撤回加购与关系线续接 |
| halftone | 复古印刷，网点方向 | 粗黑双格、网点套印、上层印签抽离揭示下层 |

七套均经当前用户认可，原完整成片为1080×1920、30fps、1100帧。`evidence/recipes/`保留原片哈希和认可范围；`examples/recipes/`保留77份实际专业计划、分镜及源特定帧函数。原色、角落真圆、上移字幕为共同保护，并不要求全片人物固定角落；已认可首尾大圆窗可延续。

这些案例中的财经理念是原口播内容，示意物品和单位不是事实证据。换素材必须重新建立原句、关系、图像任务、对象、动作、结果、读窗和交接，不继承耳机、数量、三项建议或固定秒点。

## 统一命令

从插件根目录执行，路径含空格时加引号：

```sh
node scripts/studio.mjs doctor
node scripts/studio.mjs families
node scripts/studio.mjs branches --id A09
node scripts/studio.mjs components
node scripts/studio.mjs standards
node scripts/studio.mjs recipes
node scripts/studio.mjs resolve --recipe blueprint
node scripts/studio.mjs init --project /path/to/new-film --source /path/to/own.mp4 --recipe minimal
node scripts/studio.mjs compile --recipe /path/to/new-film/recipe.json --plan /path/to/new-film/scene-plan.json
node scripts/studio.mjs run --project /path/to/new-film
node scripts/studio.mjs preview --project /path/to/new-film
node scripts/studio.mjs plan-change --axes typography
node scripts/studio.mjs revise --from /path/to/new-film --out /path/to/new-film-v2 --axes typography --request "只调整标题和字幕"
```

`init`导入真实源片、记录哈希与配方，建立十一份待设计计划，状态为awaiting-design；它不会直接做完视频。代理完成`scene-plan.json`、`timing.json`、`plans/brief.json`、十一份专业计划和`scripts/build-project.mjs`，再运行。构建需产生`index.html`及根目录`edit-plan.json`原声映射，与旧固定运行环境兼容。布局、声音、编码与最终观看仍须检查。

只改一类时，`plan-change`区分改写与复查，`revise`另存版本并保护未选计划、原片、时间轴与原声。允许必要关联修复时用`--allow-dependent <轴ID> --reason <实际原因>`显式记录。改信息组织可重新设计场景，但视觉局部修改不能偷偷改源EDL；真正重剪需要重新建立全部源映射与锚点。

明确复现原认可案例时才使用：

```sh
node scripts/studio.mjs reproduce --project /path/to/reference --recipe clay --source /path/to/original-case-840-proxy.mp4
node scripts/studio.mjs run --project /path/to/reference
```

此命令只接受原案例已登记SHA256的840方形代理源，使用本地原声，不在仓库包含用户原始视频或最终MP4。普通用户换素材走init流程。旧`styles --all`、`recipe --style Axx`、`choreographies`和schemaVersion=1工程保持兼容；不会批量重写旧工程。

## 验证与清理

先核对分类、ID、结构依赖、源哈希和真实计划，再测新机制的短片与实际输出。不要将计划解析、CLI零采样、抽帧或音频相关性说成全速看听。依赖继续使用固定版本，Three.js在本地vendor附带许可证，无外链CDN。

新工程与验证临时文件放插件外。清理可重建帧序列、缓存和失败的中间编码；保留自有原素材、有效素材、计划源码、最终片及关键证据。GitHub同步只包含插件源码和必要资源，默认不上传用户原片、最终片、密钥或运行依赖。

两套认可编排和单独节奏修改见[编排选择与局部节奏](编排选择与局部节奏.md)。当前19套母画风按视觉语言分开，不为编排变化增加画风。
