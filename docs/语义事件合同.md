# 语义事件与制作交接

整片配方提供可用语言，语义计划为每段选择必要语言。不能因为配方中有文学引句就补一条名言，也不能为了纸页转场把所有对象强做成纸。

每个场景至少包含：id、startFrame、endFrame、sentenceIds、relation、purpose、objects、action、result、readWindow、handoff。每个对象有稳定ID、素材身份（原片/真实照片/概念图/示意）和初态/结果态。

action用“对象＋动词＋结果”表达，例如“已有物件保留在左，第二实例移到待选区后被否定”，而不是“4张图片飞入”。handoff写下一场接走哪个对象或注意力，不是只写一种特效名。

readWindow为完整可读后的[起帧,结束帧)，必须处于场景区间内。起止合法只是必要条件，CLI不能替代实际字形、遮挡和读完测试。因果要求条件/机制/结果依据；并列项保持同层；引用要求逐字原文与来源；人物寓言须声明虚构或真实来源。

源片变更后重新建立原句和关系；本包自有素材示例只演示计划与现有实现的映射，不是新稿的默认内容。原声、字幕、图解和动作共用时间来源；动效不能反过来改写原意。

`compile`输出的是可交接制作计划，明确标为planning-only。逐场信息组织必须位于配方候选池中。检查顺序、覆盖、引用和对象ID，不会自动生成新图片，也不会把八个示意筹码说成真实金额。

实际工程完成后记录：输入哈希、读取标准、修改字段、最终HTML/MP4哈希、真实编码检查范围与人工观看范围。复用S05方法可以引用其证据，但新体系编译计划不能冒充重新做出了一条视频。
